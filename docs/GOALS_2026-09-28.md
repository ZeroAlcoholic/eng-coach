## §0 共同條款（每個 Phase 都貼；承 2026-09-24 §0，新增以下）

**付費呼叫（2026-09-28 使用者裁決：驗測自己徹底跑完，不停下等授權；避免昂貴模型）**
- 本藍圖的 D、E 兩階段**零新 API 呼叫**；量測全由純函式從既有紀錄推出。違反即 GOAL 不成立。
- 付費只在三處：H2 screening、F2 TTS 合成、F3 合成 E2E。執行前**印**估價（句數、分鐘數、模型名）進回報，然後**直接執行**；不詢問、不等待。`models.list` 零 token 可直接用。
- 模型選擇固定，不得升級：TTS 用 `gemini-3.8-flash-lite-tts`（合成台詞不需音質，只需 ASR 聽得懂；若 F3-b 低於門檻才換 `gemini-3.8-flash-tts` 重跑一次，並登錄）；文字 judge 用出貨值 `gemini-3.8-flash`（screening 必須對出貨模型才有效）；Live 用出貨值 `gemini-3.8-live`（同理）。**永不**呼叫 pro、extended-thinking、native-audio 等其他模型。
- 硬上限寫在程式裡，不在人的自制力裡：F2 每次執行 ≤ 60 句；F3 每支測試 ≤ 12 句、Live ≤ 4 分鐘，F3-g ≤ 13 分鐘且整輪只跑一次；H2 每模型 ≤ 6 fixture × 5 次。任一上限由測試程式 `expect` 斷言，超出即 fail 並中止。
- 重跑規則：快取命中零費用；同一檢查 fail 最多重跑一次，第二次仍 fail 即登錄，不再嘗試。
- CI 不得設 `SCREEN`／`SYNTH`；`npm test` 在 CI 必須跳過這兩支測試（`describe.skipIf`）。

**金鑰與快取**
- `.synthetic-cache/` 加進 `.gitignore`（目前沒有）。快取檔名＝文字 sha256，不含文字本身。
- 每次 commit 前：`git diff --cached | grep -E "AIza[0-9A-Za-z_-]{20,}"` 零命中；`npm run build` 後 `grep -r AIza dist/` 零命中；F 階段另加 `grep -r AIza .synthetic-cache/ *.log` 零命中。

**用詞邊界（新增一級）**
- vitest 替身＝「本機流程正確」；screening＝「晉級／淘汰」；**合成 E2E＝「合成已驗證」**（只證協定、生命週期、pipeline 在真實音訊成立；不證手機 UX、麥克風授權、教學法對人有效）；真機未跑＝blocked。跨級用詞＝違反。

**舊資料**
- 任何新欄位缺席＝unknown，不進分母、不猜值，與 `aids` 缺席同規則。每個新欄位至少一條「舊紀錄無此欄仍可讀、讀數不變」測試。

**不變量（新增）**
- 不新增量測用 API 呼叫；合成學習者是腳本化固定台詞，不是 LLM 代理。
- 註解只寫機制與「另一種寫法錯在哪」；量測數字、個案細節留在回報與 log。

## Phase D — 量測誠實

**GOAL**
讓 Home 的三個讀數與 judge 的 CEFR，只反映學習者「自發、未受助、以目標語」的產出；讓每一個焦點都能在之後的正式 session 被量到有沒有解決。

**範圍**：`kernel/types.ts`（`TranscriptTurn`、`SessionRecord`、`SessionReview`）、新增 `apps/coach/annotate.ts`、`prompt.ts`（只匯出 `HELP_TRIGGERS` 常數）、`ai/review.ts`、`uses.ts`、`readouts.ts`、`focus.ts`（型別）、`finalize.ts`、`Practice.tsx`（按鈕記 turn 索引、傳 `recycled`、FocusCard 改讀 outcome、微 session 傳空參數、120 秒安全網）、`Home.tsx`（只抽出 `Readouts.tsx`）、對應測試、`ARCHITECTURE.md`「Readouts」段、`ROADMAP.md`。不碰 transport／AudioEngine／session owner／db／pack。

**做法邊界**
- D1 `annotateTurns(transcript, language, aidedTurnIdx)` 純函式，於 finalize 呼叫，結果寫回 `SessionRecord.transcript` 的每個 turn（選填 `echo`／`aided`／`l1`）。回聲＝learner turn token 覆蓋率 ≥0.8 落在前一 coach turn（en ≥3 詞、ja ≥6 字）；aided＝命中 `HELP_TRIGGERS` 的 turn 之後的下一個 learner turn，加上 Practice 記錄的按鈕索引；`l1`＝en 情境 learner turn 含 Han／假名，ja 情境純函式永不標、由 judge `l1Fallbacks` 回填。
- D2 judge prompt：echo turn 前綴 `[repeated after coach]`、l1 turn 前綴 `[contains Chinese]`，皆不作 can-do 證據；objective 只有完全以目標語完成才 met；新欄 `l1Fallbacks: {said, target}[]`（≤5，`said` 須為 learner turn 子字串）；全為回聲或全為中文→`unavailable`。`uses.ts` 與讀數 a 排除 echo／aided／l1 turn。
- D3 微 session 呼叫 `composeSystemInstruction` 時 dueItems、weakObjectives、arc 傳空。
- D4 finalize 在 `applyReview` 後以 fresh profile 算 `pickFocus`，存 `focus: Focus`（結構）；微 session 存 `drilledFocus: { sourceSessionId }`；舊字串 focus 視為 unknown。
- D5 讀數 c＝焦點解決率：焦點型別在之後兩場正式 session 的 `review.errors` 未再出現即解決；來源列表分「有練／沒練」；後續不足兩場 value 為 null。
- D6 Practice 把 `dueItems` id 傳入 finalize，存 `recycled: string[]`；讀數 b 分母＝視窗內各場 recycled 之和，分子＝非 echo／l1 的使用。
- D7 `finalize.ts:130` 註解改一次取樣；Home 只搬出 `Readouts.tsx`，不改邏輯。
- D8 微 session 120 秒安全網走既有 Stop；prompt 仍要求 90 秒收尾。

**GOAL CONDITION（全部為真才算 completed）**
- [ ] 六份既有 fixture 經 `annotateTurns` 零標記；新增四份 fixture（回聲、口說求助、en 夾中文、ja 夾中文）各標對；ja 情境純函式永不標 `l1`。（vitest）
- [ ] 純回聲 fixture、純中文 fixture 各回 `unavailable`，理由文字可辨。（vitest，judge 以替身回傳）
- [ ] `l1Fallbacks.said` 不是子字串者被驗證器丟棄；`target` 空字串者丟棄。（vitest）
- [ ] 讀數 a、b、c 各以 0／1／5+ 場 fixture 手算相符，且排除 echo／aided／l1 後數值可逐筆追回。（vitest）
- [ ] 讀數 c：焦點有練／沒練兩組分開；後續不足兩場為 null。（vitest）
- [ ] 同 session finalize 兩次 focus 只寫一次；舊紀錄 focus 為字串、無 `recycled`、turn 無註記時三讀數輸出與 v3 完全相同。（vitest）
- [ ] 微 session prompt 不含「Spaced review」「still aren't solid」「連續劇」；正式 session 不受影響。（vitest）
- [ ] 假時鐘 120 秒後微 session phase 進 stopping；正式 session 無此計時器。（vitest）
- [ ] 原始碼 grep：`readouts.ts`／`progress.ts` 不讀 `l1Fallbacks`；`kernel/` 無 UI 匯入。（grep）
- [ ] lint／tsc／vitest／build 全綠；dist 無 `AIza`。
- [ ] `ARCHITECTURE.md` Readouts 段改為三個新定義；`ROADMAP.md` 加 Batch R2。
- [ ] 真機微 session 語音流程 → **blocked**（無麥克風），由 Phase F 的 F3-e 補「合成已驗證」。

## Phase E — 口音與句型

**GOAL**
讓教練場上有聲學依據的口音回饋能被記住並在下一場延續；讓學習者句中夾中文的詞彙缺口被當場接住、進複習、成焦點；讓有槽位的句型換了填充詞仍被認出是「用出來」。

**範圍**：`prompt.ts`、`ai/review.ts`（與 D2 同一次改）、`ai/items.ts`、`uses.ts`、`focus.ts`、`kernel/types.ts`（`SessionReview.pronunciationNotes`、`LearnedItem.frame`）、對應測試與 fixture、`ARCHITECTURE.md`。不碰 Shadowing／AudioEngine／transport。

**做法邊界**
- E1 口音：回饋改為「阻礙理解或同一音重複時才給，三到四回合至多一次，從閉集清單點名（/θ/ /ð/、字尾 /t d k/、/iː/ vs /ɪ/、詞重音、句尾語調），示範一次、請他說一次」；加「逐字稿來自語音辨識，近音詞除非上下文證明否則不標 wordChoice」。
- E2 judge 抽 `pronunciationNotes: string[]`（≤3，每條為教練 turn 子字串）；下一場 prompt 列「上次教練點過的音」。不進 ErrorType、讀數、EWMA。
- E3 grammar 項目選填 `frame`（`___` 標槽位）；驗證器：≥1 個長度 ≥2 的錨點、每錨點為 example 子字串；`uses.ts` 對有 frame 的項目用錨點依序比對；不接受模型 regex。
- E4 夾雜輔導 prompt 段：en 立刻給目標語詞加繁中 gloss、請整句英文重說、教練不切中文；ja 教練可中文解釋、學習者重說須完整日文；同詞第二次只提示首音。抽詞 prompt 優先收錄以中文代替的詞，example 用教練的目標語版本。
- E5 `focus.ts` 加 `kind: "gap"`（`l1Fallbacks` ≥2），優先序 meaning > gap > recurring > cando；micro 指令列全部 target 詞、不含中文 said 詞。

**GOAL CONDITION**
- [ ] prompt.test：閉集清單字串存在、「brief accent feedback」不存在；近音詞指示存在；en／ja 各斷言夾雜段存在且既有「求助」段原文不變。（vitest）
- [ ] fixture：教練點名 th 一次→`pronunciationNotes` 一條；沒說→空；捏造句被丟；grep `readouts.ts`／`progress.ts`／`readouts` 不讀此欄。（vitest＋grep）
- [ ] frame：「I'd rather stay than go」命中「I'd rather ___ than ___」；錨點順序反不命中；無 frame 舊項目行為不變；frame 含 `.*` 等字元不具 regex 意義。（vitest）
- [ ] items fixture：夾雜「預約」→抽出目標語詞且 example 為教練版本（judge／items 以替身回傳固定 JSON，驗證 parser 與後續寫入）。（vitest）
- [ ] focus.test：三種既有優先序衝突案加 gap 案各選對；gap 的 micro 指令不含任何 `said` 中文詞。（vitest）
- [ ] lint／tsc／vitest／build 全綠；dist 無 `AIza`。
- [ ] 教練是否真的照清單點名、是否真的接住夾雜 → **blocked**（真機），由 F3-i 補「合成已驗證」；模型對 met 規則的遵從率由 H2 給讀數。

## Phase F — 合成學習者

**GOAL**
在沒有麥克風與人類的情況下，讓 v3 標為 blocked 的生命週期與學習迴圈檢查，能對真實 `gemini-3.8-live` 跑出二元判定，且每次執行費用有硬上限。

**範圍**：新增 `apps/coach/synthetic/SyntheticLearnerAudio.ts`、`scripts/synth-lines.ts`、`apps/coach/synthetic.e2e.test.ts`、`.gitignore`、`docs/DEVICE_E2E.md`「合成」段。不碰 `AudioEngine`／`gemini-direct`／`session.ts`／UI。

**做法邊界**
- F1 `SyntheticLearnerAudio implements SessionAudio`：`start` 立即成功；`playPcm` 累積至緩衝並依 PCM 長度排程 `onDrained`；`isPlaying` 依排程；`pauseMic`／`resumeMic` 只切旗標；`beginCoachTurn`／`endCoachTurn`／`lastCoachTurn` 以緩衝實作；`say(pcm16k)` 以 20 ms 幀（320 samples）呼叫 `onChunk`，句尾補 600 ms 靜音。
- F2 `synth-lines.ts`：只讀 `GEMINI_API_KEY`；把 fixture 的 learner turns（含四份新 fixture 的夾雜句）以 `gemini-3.8-flash-lite-tts` 合成 24 kHz PCM，`resampleLinear` 至 16 kHz，存 `.synthetic-cache/<sha256>.pcm`；已存在則跳過。執行前印句數與估價，然後直接跑；≤60 句由程式斷言。
- F3 `SYNTH=1` 才跑：`PracticeSession`＋真 transport＋F1 替身；等 cue 為「you」才送下一句；結束走 `finalizeSession` 記憶體 deps；每支測試台詞 ≤12 句、Live ≤4 分鐘，由程式斷言；F3-g（GoAway）單獨測試、≤13 分鐘、整輪只跑一次。全部檢查在同一次 `SYNTH=1` 執行中跑完並寫入 `DEVICE_E2E.md`，不分次請示。

**GOAL CONDITION**

- [ ] F2 重跑第二次零 API 呼叫（計數斷言）；快取檔名不含文字；`.synthetic-cache/` 已 gitignore；grep `AIza` 於 cache 與 log 零命中。（node 腳本＋grep）
- [ ] F3-a 每次 cue 轉「you」時 `isPlaying()` 為 false。（合成）
- [ ] F3-b 送 N 句→user turn 數 ≥ 0.8N。（合成；低於門檻＝fail 並登錄 U4，不以人聲補測）

- [ ] F3-d 「提示一下」之後的 learner turn `aided===true`。（合成）

## §4 部署與檢查（每個 Phase 合併後貼）

**部署機制（程式事實）**：push `main` → `.github/workflows/pages.yml` 依序 `npm ci`→lint→typecheck→`npm test`→build→upload→deploy；`vite.config.ts` production `base: "./"`。沒有 staging，所以 PR 合併前的本機四綠就是唯一閘門。

**合併前（本機）**
- [ ] `npm run lint && npm run typecheck && npx vitest run && npm run build` 四綠，輸出貼進回報。
- [ ] `git diff --cached | grep -E "AIza[0-9A-Za-z_-]{20,}"` 零命中；`grep -r AIza dist/` 零命中。
- [ ] 恰好一輪四路 code review（缺陷／沉默失敗／型別設計／測試覆蓋），修真缺陷，不加碼。
- [ ] 每個 commit 原子、訊息寫「改動→行為差異→機制」；破壞性指令不與 commit 同行。

**合併後（線上）**
- [ ] Actions run 連結，build／deploy 皆 success。
- [ ] `curl -s -o /dev/null -w '%{http_code}' https://zeroalcoholic.github.io/eng-coach/coach.html` 為 200；線上 `coach.html` 引用的 hashed asset 名與本機 `dist/assets` 完全一致（三個檔名逐一列出）。
- [ ] 線上 `manifest.webmanifest`、`sw.js` 皆 200。
- [ ] 真 Chrome 開線上頁：Console 無 CSP 違規、無未捕捉錯誤；⚙️ 覆寫模型名後不需改端點（H1 合併後）。
- [ ] Lighthouse a11y 100（Chrome devtools）。
- [ ] 舊資料回歸：以 v3 匯出的 LearningPack 匯入線上頁，Home 三讀數與匯入前一致、無 NaN、無空白列。

**回滾**
- [ ] 任一線上檢查 fail：`git revert <merge commit>` 推 main 觸發重部署，不 force push、不 reset；回報寫明 fail 的檢查與 revert commit。

**回報格式**：沿用 2026-09-24 §0 的六標記與驗收案例表；每個 Phase 另附「覆蓋證偽欄」一輪：對每一項問「拿掉它，GOAL 還成立嗎」，成立者列為已撤或未做。
