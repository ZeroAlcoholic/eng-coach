# eng-coach 三階段 GOAL 指令（可直接貼給 /goal）

用法：貼「§0 共同條款」＋任一 Phase 區塊。Phase A、B 可平行（各開分支）；Phase C 在 A、B 合併後才開。
依據：`docs/BLUEPRINT_2026-09-24.md`（事實、相依性、不變量）。

## §0 共同條款（每個 Phase 都貼）

**專案**：`D:\Python\EnglishDialogue\eng-coach`，純瀏覽器 PWA，零後端，GitHub Pages。先讀 `docs/BLUEPRINT_2026-09-24.md` §0–§2 與 `ARCHITECTURE.md`，再動手。

**金鑰（絕對）**
- Gemini key 只存在兩處：使用者手機 `localStorage`（runtime）、開發機環境變數 `GEMINI_API_KEY`（僅供 node 腳本）。
- 禁止把任何 key、`AIza…` 字樣、或帶 key 的 URL 寫進：原始碼、測試、fixture、`public/`、`docs/`、console.log、錯誤訊息、commit、PR。
- 每次 commit 前執行 `git diff --cached | grep -E "AIza[0-9A-Za-z_-]{20,}"` 必須零命中；`npm run build` 後 `grep -r AIza dist/` 必須零命中。
- 呼叫真 API 前先說明目的與預估費用；`models.list` 零 token 可直接用；Live 連線與 generateContent 屬付費，非驗收必要不呼叫。

**嚴謹開發**
- 順序固定：讀碼→寫工單（改哪幾檔、機制、驗收案例）→實作→測試→自審→回報。工單先貼出再動手。
- 真實優先：不用 behavioral fake 冒充正式行為；測試替身只在注入邊界（transport／audio／時鐘／IndexedDB），且替身不得決定業務邏輯。
- 每修一個缺陷至少一條對應測試，測試名稱寫出被防止的行為。
- 每個 commit 原子、可獨立 revert、訊息說明「改動→行為差異→機制」；不混入無關檔案；不 `--no-verify`、不 force push、不 `reset --hard`。
- 合併前 `npm run lint && npm run typecheck && npx vitest run && npm run build` 全綠，並附輸出。
- 範圍外的發現只寫進回報「登錄」段，不動手。想加一步前先問「拿掉它，GOAL 還成立嗎」，成立就不做。

**Clean Code**
- 函式單一目的、可命名；超過一屏就拆。命名以領域詞（`resumeHandle`、`awaitingMic`），不用 `data`/`tmp`/`flag`。
- 對不可信輸入（模型 JSON、匯入檔、IndexedDB 舊資料）禁止 `as T`；用 validator 收窄成型別。
- 狀態用 discriminated union 並 `never` 檢查窮盡；不用布林旗標組合表達狀態。
- 註解只寫機制與「另一種寫法錯在哪」；不寫歷史、不寫 TODO 塞債。
- 不留死碼、不留註解掉的程式；改了行為就同 PR 改文件。

**SOLID（本專案的具體落點）**
- **S**：`gemini-direct` 只管 WebSocket 協定與訊息解析；`AudioEngine` 只管擷取與播放；`Practice` 只管 UI；資源所有權與取消由單一 session owner 持有；validator 與 prompt 分檔。
- **O**：新的伺服器訊息（如 `goAway`）以新增 handler 擴充，不在 UI 層加 `if`。
- **L**：`Review | Unavailable` 兩型別各自完整，呼叫端不得把 `Unavailable` 當空 `Review` 用。
- **I**：handler 介面只暴露 UI 需要的事件；不把 SDK 型別漏到 `Practice`。
- **D**：`Practice` 依賴 session 介面，測試以注入替身驅動；不 `new` 具體 transport 於 UI 內。
- 不引入：狀態機套件、DI 容器、事件 bus、plugin registry、多供應商抽象、schema 編譯器。

**不變量**：零後端、BYOK、IndexedDB＋LearningPack、無 streak／提醒、極簡 UI（一屏一主動作）。

**回報格式**（每 Phase 結束）
1. 六標記逐項：completed／partial／running／deferred(附因)／blocked／out-of-scope。blocked 前附排除清單（transient？自造？替代？）。
2. 每項改動一行：「改動→行為差異→結果動，因為[機制]」。
3. 驗收案例表：案例｜層級（vitest／Chrome 替身／真機）｜結果｜證據（測試名或指令輸出）。
4. 用詞邊界：替身層只准「本機流程正確」；screening 只准「晉級／淘汰」；真機未跑就寫 blocked。
5. 登錄段：範圍外發現、文件漂移、未來債。
6. 完成後跑**恰好一輪**四路 code review（缺陷／沉默失敗／型別設計／測試覆蓋），修掉真缺陷，不加碼。

## Phase A — Session 生命週期

**GOAL**
在 `gemini-3.8-live` 上，讓一場練習的長度、開始、停止與「換你說」的時機，完全由使用者與真實資源狀態決定，而不由連線上限、模型完成訊號或啟動中的競態決定。

**範圍**：`src/api/gemini-direct.ts`、`src/audio/AudioEngine.ts`、`src/apps/coach/Practice.tsx`、`src/kernel/overrides.ts`、新增 session owner 檔、對應測試、`ARCHITECTURE.md` 相關段。不碰 `db`／`ai`／`finalize`／`pack`（Phase B 範圍）。

**做法邊界**
- `DEFAULT_LIVE_MODEL` → `gemini-3.8-live`；3.1 經既有 override 可回退；transport 對模型名零假設。
- setup 加 `contextWindowCompression: { slidingWindow: {} }`；`handleMessage` 處理 `m.goAway`，以既有 `resumeHandle` 自動重連**一次**，對外只多 `onReconnecting`／`onResumed` 事件；重連失敗才走 `onClose`。
- 抽單一 session owner（hook 或類別，自寫不加套件）：持有 client、engine、`generation` 計數；每個 `await` 後驗 generation，失效即釋放剛取得資源；`AudioEngine.start` 三步任一失敗釋放已取得者；新增 `onDrained`（最後 scheduled node ended）。
- phase 為 `connecting→awaiting-mic→live→stopping→saved→(analysing|analysis-failed)` 的 discriminated union；任何 phase 可 Stop；Stop 先 teardown 裝置再存快照；`saved` 即可離開，分析背景寫回同 sessionId。
- 「換你說」＝`turnComplete` 且 `onDrained` 兩者齊備；`interrupted` 立即切。
- `proactivity.proactiveAudio` 與 `enableAffectiveDialog` 各自獨立 flag（預設開），不調 prompt。
- 不做 extended-thinking（SDK 2.7.0 無 `interactionStatus`）。

**GOAL CONDITION（全部為真才算 completed）**
- [ ] 注入 `goAway{timeLeft:"5s"}` → 自動重連，sessionId、草稿、逐字稿連續；重連失敗 → 逐字稿仍在、進入可存檔重開路徑。（Chrome 替身）
- [ ] 在 connect／getUserMedia／worklet 載入三階段分別 Stop、unmount、拒權 → 無殘留 `MediaStreamTrack`（readyState ended）、AudioContext closed、socket closed；舊 session callback 不改新 session state。（Chrome 替身）
- [ ] 「練習中」不早於麥克風就位；connecting／awaiting-mic 期間 Back／Stop 可用。（Chrome 替身）
- [ ] 最後 chunk 與 turnComplete 同包、0.85 倍速、長句、barge-in 四案：音訊仍在播時「換你說」不出現。（vitest 對 AudioEngine 時鐘＋Chrome 替身）
- [ ] `Practice.tsx` 不再直接持有 client／engine ref；不 import SDK 型別。（grep 證明）
- [ ] 使用者主動 Stop 期間收到 goAway 不觸發重連。（vitest）
- [ ] lint／tsc／vitest／build 全綠；`dist/` 無 `AIza`。

## Phase B — 資料真實性

**GOAL**
讓每一筆寫進 IndexedDB、顯示在畫面、匯入自備份的資料都是真的：「已儲存」等於 transaction 已 commit，評量只宣稱文字逐字稿能證明的事，同一 session 重做收尾是 no-op，備份不合法就整包拒絕。

**範圍**：`src/kernel/db.ts`、`src/kernel/pack.ts`、`src/apps/coach/ai.ts`、`finalize.ts`、`progress.ts`、`HistorySheet.tsx`、`Home.tsx` 匯入入口、`kernel/types.ts`、對應測試、`ARCHITECTURE.md`／`ROADMAP.md`。不碰 transport／audio／Practice 生命週期（Phase A 範圍）。

**做法邊界**
- `db.run` 於 `tx.oncomplete` resolve、`onabort`／`onerror` reject；對齊已正確的 `putItems`／`putArcWithScenario`。
- `summariseSession` 回傳 `SessionReview | ReviewUnavailable`（discriminated union）；三次全失敗回 `Unavailable`，不再以目標等級假冒 cefr。prompt 移除 pronunciation；`fixes`／`errors` 的 `example` 須子字串命中學習者某 turn 才採用；CEFR 只由 grammar／vocab／interaction 推。
- 每個 AI 能力（scenario／items／review／replies／arc／extras／translate）各一個最小 validator（enum、範圍、必要欄位），取代 `as T`；無效樣本作廢不混入 median。
- finalize：抽詞成功、評量 Unavailable 時，session 存「逐字稿已存、評量未完成」；`HistorySheet` 提供重試評量。
- `SessionRecord.finalize` 步驟帳 `{transcriptSaved, itemsSaved, reviewApplied, arcAdvanced}`；items 帶 `sourceSessionId` 去重；profile 寫前讀最新再合併；舊紀錄無此欄視為全 true。
- `importPack(input: unknown)`：驗根物件、version、profile enums、每 record 必要欄位型別、arc↔scenario 參照；全過才寫；匯入前回報「新增 N／覆蓋 M」。政策：整包拒絕。
- 文字模型：以 6 份代表逐字稿 fixture（去識別、無 key）screening `gemini-3.5-flash` vs `gemini-3.8-flash`（example 命中率、validator 失敗率、延遲），不劣化才切；同組 fixture 跑 judge 1 次 vs 3 次 ×5 seed，變異降幅 <1 級距才改 1 次。付費呼叫前先報預估。
- `ARCHITECTURE.md:115` 改為實際取樣次數與 Unavailable 分支；ROADMAP 加本 Phase。

**GOAL CONDITION**
- [ ] `onsuccess` 後強制 `tx.abort()` → promise reject、草稿存活；正常路徑「已儲存」只在 complete 後出現。（vitest，fake-indexeddb 或注入）
- [ ] judge 六案：三次全失敗／部分成功／cefr 非法／subscore 超界／example 不在逐字稿／只有教練說話 → 皆不寫入任何評量數字；Home 恢復卡不顯示 CEFR。（vitest）
- [ ] 每個 AI 能力對「缺欄位」「錯型別」「enum 外值」各一案 validator 拒絕。（vitest）
- [ ] 同 session finalize 兩次、清草稿失敗後恢復、抽詞單獨失敗、兩分頁競爭 → 詞卡數、attempts、error count 只計一次；另一分頁的偏好不被回寫。（vitest）
- [ ] 五種無效 pack（非法 language、缺 objectives、錯型別 transcript、缺 arc 參照、版本不支援）皆不改任何有效資料；正常 round-trip 保 FSRS 狀態。（vitest）
- [ ] 舊格式 session／profile／pack 無新欄位仍可讀、可顯示。（vitest）
- [ ] 文字模型與取樣次數 screening 結果以表格附上，用詞只准「晉級／淘汰」。
- [ ] 原始碼中對模型輸出／匯入檔零處 `as T`。（grep 證明）
- [ ] lint／tsc／vitest／build 全綠；`dist/` 與 fixture 無 `AIza`。
- [ ] `ARCHITECTURE.md`／`ROADMAP.md` 已同步。

## Phase C — 學習效度（A、B 合併後）

**GOAL**
讓使用者在 Home 看得到三個零 API、可追回來源 session 的進展讀數——無提示 can-do 達成率、教過 chunk 的主動使用率、錯誤型別復發率——並在每集結尾只給一個焦點、可立刻再練 90 秒。

**範圍**：`objectives.ts`、`srs.ts`、`progress.ts`、`finalize.ts`、`Home.tsx`、`Practice.tsx`（僅結尾 UI 與微 session 入口）、`Sheet.tsx`、`kernel/types.ts`、對應測試、`ROADMAP.md`。

**做法邊界**
- ledger 加 `aided: boolean`（該 turn 前是否觸發 hint／翻譯／建議回覆；Practice 已有事件）；讀數 a＝無提示達成／總達成。
- 集尾純函式：本 session prompt 帶入的 due items 是否出現在學習者逐字稿（子字串／詞幹）→ `LearnedItem.uses.push(sessionId)`；讀數 b＝近 5 場被使用的 due item 比率。
- 讀數 c＝近 5 場中出現於 ≥2 場的 `ErrorType` 數（E1 tally 已有）。
- 呈現：既有 stat chip 旁一個小趨勢符號；點入列出來源 session。不做儀表板、不做圖表。
- 集尾摘要只挑一項焦點（阻礙意義 > 復發 > 未達 can-do），提供「▶ 再練 90 秒」：同 scenario、`contentContext` 縮到該焦點、上限 90 秒、`finalize.kind="micro"`、不進 CEFR EWMA、只進 a／b／c。可跳過，無提醒。
- `Sheet` 改原生 `<dialog>.showModal()`，關閉還焦觸發鈕。

**GOAL CONDITION**

- [ ] 每個讀數可點回產生它的 session 列表且一致。（Chrome）
- [ ] 微 session 不改 level／EWMA；a／b／c 反映微 session；可跳過；無任何提醒或計時壓力字樣。（vitest＋Chrome）
- [ ] 焦點選擇在三種優先序衝突案各選對。（vitest）
- [ ] Dialog：Tab／Shift+Tab 不逃出、Esc 關閉、還焦原鈕；Lighthouse a11y 100。（Chrome）
- [ ] 舊資料無 `aided`／`uses` 仍可計算（視為 unknown，不計入分母）。（vitest）
- [ ] lint／tsc／vitest／build 全綠；無 `AIza`。
- [ ] 微 session 真機語音流程 → blocked（無麥克風），明說。
- [ ] `ROADMAP.md` 記錄三讀數定義與微 session 政策。
