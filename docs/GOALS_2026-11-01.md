## §0 共同條款（每個 Phase 都貼）

**不估工時**（2026-11-01 使用者裁決）：回報只寫 completed／partial／blocked 與判準讀數，不寫天數或小時。

**台灣語境（2026-11-01 使用者裁決：務必確保台灣語境、台灣腔與台灣用語）**
- 任何會產生中文的程式路徑（prompt、生成欄位、UI 文案、測試 fixture）一律台灣繁體與台灣用語。禁用對照：信息→資訊、軟件→軟體、視頻→影片、質量→品質、默認→預設、螢幕／滑鼠／互動／連結／資料庫。
- 規則只有一個正本（`ai/client.ts` 的 `ZH_TW_RULE`）；其他位置只准引用。Phase T 未合併前，任何新 prompt 不得各自再寫一份。

**零新付費呼叫**：本藍圖四個 Phase 皆不新增 API 呼叫。唯一付費＝Phase C 的一支合成腳本（`SYNTH=1`，≤12 句／≤4 分鐘，由程式 `expect` 斷言；印估價後直接跑，不詢問）。

**用詞邊界**：vitest 替身＝「本機流程正確」；合成 E2E＝「合成已驗證」；真機未跑＝blocked。跨級用詞＝違反。開發機無麥克風，真模型判定一律走合成學習者，回報不得列「請真人測」。

**舊資料**：每個新欄位（`persona`、`prefs.turnCue`、`prefs.taskCardOpen`）缺席＝舊行為；至少一條「舊 pack／舊紀錄無此欄仍可匯入、讀數不變」測試。

**金鑰**：commit 前 `git diff --cached | grep -E "AIza[0-9A-Za-z_-]{20,}"` 零命中；build 後 `grep -r AIza dist/` 零命中。

**不變量**：零後端／BYOK；不加 function calling、狀態機套件、DI、頭像配圖背景音、提醒、新學習機制；只搬 JSX 的項目不得改 handler 語意；註解只寫機制，不寫數字與個案。

**每個 commit 的 DoD**：lint／tsc／vitest／build 全綠；對應二元判定全部為真；恰好一輪唯讀審查子代理（工程審查），結論由主代理親驗後採信；`ROADMAP.md` 加一行。

## Phase T — 台灣語境機械化

**GOAL**
讓任何一個會產生中文的呼叫點都無法產出簡體字或中國用語；規則一個正本，違反即被驗證器丟棄；Live 教練的台灣國語有具體語例。

**範圍**：`ai/client.ts`（常數＋自動附加）、`ai/scenario.ts`、`ai/arc.ts`、`ai/items.ts`、`ai/replies.ts`、`ai/review.ts`、`ai/translate.ts`（刪各自中文變體句、parser 接驗證器）、新增 `kernel/zhTw.ts`、`prompt.ts`（語例）、對應測試、`ARCHITECTURE.md` 一段。不碰 transport／AudioEngine／session／db／UI。

**做法邊界**
- T1 `ZH_TW_RULE` 常數；`generateJson` 在 prompt 末自動附加；六個呼叫點刪掉自己的版本。
- T2 `zhTwProblem(text)` 純函式：閉集簡體字表（≥40 字，避開日文當用漢字）＋閉集中國用語表；只掃標記為中文的欄位（日文欄位不掃）；命中→該樣本 `Invalid`；judge 走既有丟樣本→`unavailable` 路徑。
- T3 台灣國語段加「說／不說」各 ≥5 個語例、禁兒化、台灣時間用語；前情提要與規劃拍引用同一常數。

**GOAL CONDITION（全部為真才算 completed）**
- [ ] `generateJson` 替身收到的每個 prompt 以 `ZH_TW_RULE` 結尾。（vitest）
- [ ] `grep -rn "Traditional Chinese" src/apps/coach/ai` 只命中 `client.ts`。（grep）
- [ ] 含「软件」「信息」「这个」的情境／劇集／詞義／提示／評語／翻譯樣本被拒，訊息指出命中字詞；含「軟體」「資訊」「這個」通過。（vitest，每個 parser 各一組雙側）
- [ ] 日文 contentContext 含「会計」「学校」不被拒。（vitest）
- [ ] judge 一份 wins 含簡體→樣本丟棄→零樣本時 `unavailable` 理由可辨。（vitest）
- [ ] `composeSystemInstruction` 輸出含全部「說」與「不說」語例；語例常數只定義一次。（vitest＋grep）
- [ ] 既有 436 測試全綠，fixture 無簡體字（`zhTwProblem` 掃 `fixtures/transcripts.ts` 中文 turn 為 null）。

## Phase I — 情境帶入

**GOAL**
讓學習者在開口前就知道自己是誰、對方是誰、這場要做到什麼；讓同一個角色在整條故事線用同一個聲音；讓情境描述是處境而不是練習說明。

**範圍**：`kernel/types.ts`（`persona`、`prefs.taskCardOpen`）、`kernel/packSchema.ts`、`Home.tsx` 設定 Sheet（三個輸入）、`prompt.ts`（身分段、入戲開場句）、`voices.ts`、新增 `TaskCard.tsx`、`Practice.tsx`（掛卡、傳 seed）、`defaults.ts`（內容改寫）、對應測試。零 API。

**做法邊界**
- I1 `persona?: { name?, jobTitle?, orgType? }`，各 ≤40 字 trim；prompt 段只在任一欄非空時存在；en 用稱呼與職務改寫 userRole，ja 只用稱呼。
- I2 `pickVoice(language, seed)` FNV-1a 取模；seed＝`arc?.arcId ?? scenario.id`。
- I3 `TaskCard`：你扮演／對方／這場要做到（前 3）／可以用的句子（前 3）；開始前展開、live 收合可點開；狀態存 prefs。
- I4 單場開場加一句入戲場景句（台灣國語），位於規劃句之前；arc 情境維持 recap 優先。
- I5 預設情境全部改寫為種子格式（地點、具名對方、要達成的事、一個阻力），日文預設描述改繁中；id 不變。

**GOAL CONDITION**
- [ ] 有 `name` 則 prompt 含該名與 address 指示；全空則整段不存在；>40 字截斷；pack round-trip 保留；舊 pack 無 persona 可匯入。（vitest）
- [ ] 同 seed 同音色 ×100；100 個不同 seed 覆蓋池中每個音色；`voices.ts` 無 `Math.random`。（vitest＋grep）
- [ ] TaskCard 三種資料形態（完整／objectives 空／phrases 空）渲染正確；收合狀態寫入 prefs。（vitest）
- [ ] Chrome 替身 390×844：開始前任務卡完整可見；live 中收合為一列。（替身截圖，桌機已驗證）
- [ ] 單場 prompt 場景句位於規劃句之前；arc prompt 不含場景句。（vitest）
- [ ] 19 筆預設：`zhTwProblem` 為 null；contentContext 不含「練習」「不是」「流暢度」；coachRole 含人名；stable id 集合與改寫前相同。（vitest）
- [ ] 四路（I1/I2/I3/I4）皆有「缺席＝舊行為」測試。

## Phase C — 輪替與收場

**GOAL**
讓學習者不看螢幕也知道輪到自己；讓教練的收尾就是 session 的結尾，且有入戲的結局；讓靜默指示用完後學習者知道下一步。

**範圍**：`audio/AudioEngine.ts`（`chime`）、`session.ts`（`SessionAudio.chime`、cue 觸發、收場狀態、自動停止、預算用完提示）、`synthetic/SyntheticLearnerAudio.ts`（`chime` no-op）、`prompt.ts`（`CLOSING_LINE`、收場順序含結局）、`focus.ts`（微 session 結束語改同一常數）、`Practice.tsx`（收場畫面、🔔 切換）、`kernel/types.ts`（`prefs.turnCue`）、`packSchema.ts`、對應測試、合成腳本一支、`ARCHITECTURE.md` 生命週期段。不碰 transport 協定。

**做法邊界**
- C1 `chime()`：80 ms 正弦 880 Hz、增益 0.15 淡出；cue 轉「you」且非暫停／重連／收場時呼叫，並 `navigator.vibrate?.(60)`；`prefs.turnCue` 預設 true；例外一律 catch。
- C2 `CLOSING_LINE` 常數＝「今天就練到這裡」；收場第 1 步交代學習者目標的具體結果；最後一句恰為常數。owner 累積當前教練 turn 文字，含常數即 `closing`：清靜默計時、永不再 arm、phase 帶 `closing`；15 s 無學習者逐字稿→`onAutoStop`；學習者開口取消自動停止、closing 不清。
- C3 第 3 則指示後再靜默 15 s→`onNotice` 一次；學習者開口清除。

**GOAL CONDITION**
- [ ] cue 轉 you 觸發 `chime` 一次；教練說話中、暫停、重連、收場後、prefs 關閉皆零觸發；`vibrate` 不存在不拋。（vitest）
- [ ] 合成替身 `chime` 存在且無副作用。（vitest）
- [ ] 教練 turn 含 `CLOSING_LINE`（含被切成兩段 delta）→靜默指示零、假時鐘 15 s 後 stop 呼叫一次；不含→指示照送；closing 後學習者開口→不自動停；暫停中不自動停。（vitest）
- [ ] 微 session 結束語與正式 session 用同一常數；grep「好，這段結束」零命中。（grep）
- [ ] 第 3 則指示後 15 s notice 一次、不重複；開口後清空。（vitest）
- [ ] **合成已驗證**（`SYNTH=1`，一支，≤12 句／≤4 分鐘，印估價後直接跑）：教練收尾後指示數 0；session 自動結束；judge 回 review；教練最後一個 turn 含 `CLOSING_LINE`（U2′ 的讀數，不照說＝登錄、不加欄位）。
- [ ] 真機喇叭可聽度→**blocked**，參數為常數。

## Phase U — 輕鬆使用

**GOAL**
讓首頁一眼只有一個主行動；讓已授權的裝置免再點開始；讓回顧只剩一個焦點與自評；讓回顧不必等下一集寫完。

**範圍**：`Home.tsx`（搬出 `ScenariosSheet.tsx`、主按鈕規則）、`Practice.tsx`（autoStart、回顧預設可見性）、`finalize.ts`（背景下一集）、對應測試。只搬 JSX、不改資料。

**做法邊界**
- U1 首頁不捲動區：讀數條、主按鈕（未完 arc→下一集；否則 lastPracticed→再練一次；否則→換個新劇情 單場）、換個新劇情卡、金鑰卡（無金鑰時）、恢復卡（有草稿時）、一顆「情境與新增」ghost 按鈕開 Sheet。卡片編輯／匯出／刪除收進「⋯」。handler 不改。
- U2 `permissions.query({name:"microphone"})` 回 `granted` 且 `autoStart` 為真才 `start()`；其餘一律維持按鈕。
- U3 回顧預設：can-do 自評、焦點卡、第一個 win、第一個 fix；「看完整回顧」展開其餘。
- U4 `advanceStory` 不 await；`outcome.story.advanced` 可為 `"pending"`；背景完成後 tick ledger；失敗登錄不影響 outcome；Home 下一集靠既有 `advanceArc` 去重。

**GOAL CONDITION**

- [ ] Chrome 替身 390×844 不捲動可見主按鈕；首頁不捲動區 `button` 數 ≤3（不含 topbar）；`Home.tsx` 行數低於 1140。（替身＋wc）
- [ ] Sheet 內新增表單的草稿在關閉重開後仍在。（vitest）
- [ ] granted→start 一次；prompt／denied／query 拋錯／API 不存在→零次且按鈕存在；`autoStart` 假→零次。（vitest）

## §5 部署與檢查（每個 Phase 收尾都貼）

1. `npm run lint && npx tsc -b && npx vitest run && npm run build` 全綠；`grep -r AIza dist/` 零命中。
2. 每個新欄位各一條「缺席＝舊行為」測試存在（grep 測試名）。
3. 一輪唯讀審查子代理；每條結論主代理親驗後才採信；修完再跑第 1 步。
4. `ROADMAP.md` 加該 Phase 一段（機制與判準讀數，不寫工時）；`ARCHITECTURE.md` 改動段落同步。
5. commit（不 push，push 由使用者裁決）；回報用六標記之一，附每條 GOAL CONDITION 的讀數與可重跑指令；blocked 項只准是「真機」。
